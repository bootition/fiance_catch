# 用户使用手册

> 适用版本：重构后的本地单用户账本（v2 页面，schema v5）。
> 手册依据：`docs/decisions/01_refactor_spec.md`（规格）与实际页面实现核对后编写，2026-08-27。
> 当前状态：真实账单已导入，`/inbox` 有待确认 344 条等待处理（未匹配 247、人际转账 44、退款 46、其他中性 2、提现 5）。已确认账本 1961 条。支付宝收入（闲鱼收款）已按规则全部归入副业收入；剩余规则外订单继续总结。

## 1. 启动与访问

在项目根目录执行：

```
python -m uvicorn app.main:app --reload
```

浏览器打开 **http://127.0.0.1:8000**。

- 所有数据保存在本地 `.data/ledger.sqlite`（单文件，SQLite）。首次启动会自动建库/升级 schema，无需手动操作。
- 本应用是**本地单用户**系统，没有登录和权限。不要把端口暴露到公网。
- 账单原始文件不会存入数据库；导入后请继续把它们留在项目外（`D:\Mr.Q\掌控经济\消费记录`），不要放进仓库。

页面导航（顶栏）：**概览 / 导入 / 待确认（N）/ 流水 / 规则 / 批次**。

## 2. 先看懂三个核心概念

### 2.1 交易类型

| 类型 | 含义 | 参与统计 |
|---|---|---|
| 消费 | 花钱 | 计入消费与分类统计 |
| 收入 | 进钱（工资、报销、红包、利息、副业等） | 计入收入统计 |
| 调拨 | 平台余额充值、余额宝/零钱通转入转出等资金搬家 | 不计消费、不计收入；专用分类：攒股收息 / 哈利布朗 / 虚拟货币 / CS饰品 |
| 退款 | 必须关联一笔原消费，冲减它的实际成本 | 影响消费净额 |

### 2.2 分类（只认这 10 个名字，统计按名字精确归组）

| 分类 | 用途 | 是否日常类 |
|---|---|---|
| 日常三餐 | 食堂正餐、美团/淘宝外卖正餐 | ✅ |
| 出行交通 | 通勤与本地交通 | ✅ |
| 书籍学习 | 书、课程、软件、设备、文具、考试 | ✅ |
| 日常娱乐 | 奶茶零食、买菜、非外卖餐厅、服饰美妆、家居、小额网购、娱乐 | ✅ |
| 日常缴费 | 房租、保险、日用品、话费、订阅 | ✅ |
| 医疗健康 | 医院、诊所、药店、体检等 | ✅ |
| 衣物用品 | 鞋、外套、衣服、裤袜、帽子等 | ✅ |
| 被坑智商税 | 明显被割韭菜的消费 | ❌ 单列 |
| 突发消费 | 计划外突发支出 | ❌ 单列 |
| 锻炼花费 | 健身/锻炼相关 | ❌ 单列 |
| 旅游 | 旅行相关（需确认） | ❌ 单列 |
| 副业成本 | 资料/版权采购、营销推广 | ❌ 单列 |
| 副业收入 | 闲鱼虚拟资料等经营收入 | ❌ 单列 |
| 其他收入 | 除副业外的全部收入 | ❌ 单列 |
| 生活费 | 邱景衡、二姑等转账收入 | ❌ 单列 |

> 分类框是自由文本 + 下拉建议。**请使用上表的准确名字**（例如写"日常三餐"而不是"吃饭"），否则统计排行会拆成多个分类。旅行交通归"旅游"，不归"出行交通"。

### 2.3 待确认机制（为什么不能自动全分类）

第一版不接 AI，规则库初始为空，所以消费和收入**一律先停在待确认**，绝不猜。已确定的资金搬家（充值、余额宝/零钱通互转）才会自动入账为"调拨"。

待确认分两个区，**互不混用**：

- **高风险区**：退款、提现到银行卡、人际转账/红包/收款、其他中性资金流 → 只能逐笔处理。商家"收钱码/扫码收款"类支出**不是**人际转账，会进分类区（2026-08-14 修复）。
- **分类区**：未命中任何规则的普通交易 → 按商户分组批量确认。

## 3. 处理待确认（你接下来要做的事）

进入「待确认」页，从上到下分两个卡片。**推荐按下面的顺序做**，原因在每步里说明。

### 第 1 步：分类区（批量确认，247 条）

页面下方「分类区」表格按"商户 × 平台 × 方向"分组。每一行会展示**商品/说明样本、最近交易时间、笔数、合计金额**；点「查看 N 笔明细」可以展开该组每一笔的交易时间、商品说明、原始分类和金额——商户名被平台打码成 `****0` 这类样式时，主要靠商品说明辨认。

1. 看商户名与商品说明判断它是什么（比如某食堂档口、某外卖、某书店）。
2. 类型已按账单方向自动锁定：收入组只能是「收入」，支出组可选「消费/调拨」，不会再出现收入项目误选成支出。
3. 分类下拉已内置第 2.2 节的正式分类：选「消费」出现消费分类（含衣物用品），选「收入」出现收入分类；选「调拨」出现调拨专用分类（攒股收息/哈利布朗/虚拟货币/CS饰品）。
4. 点「确认 N 项」。

**搜索**：分类区顶部搜索框可以按**商户名或商品说明**搜索（例如输入"闲鱼"可找到商品说明含闲鱼的交易）。输入后等待 300ms 自动搜索，也可以按回车或点「搜索」；搜索与翻页都是局部刷新，不会跳回页面顶部。

**合并规则**：只有「商户/交易对方 + 平台 + 收支方向」三项完全相同的待确认项才会合成一组。如果发现合并不合适，点「查看 N 笔明细」展开后，每一笔都有「单独处理」按钮，可只确认这一笔，组内其他笔继续等待。明细展开区显示在该组栏目行上方。

**处理后的位置**：单笔确认或整组确认后，页面保持你原来的滚动位置，不会跳到底部。

**翻页**：分区底部有上一页/下一页、当前页附近的页码（1、2、3…）和「跳至第 N 页」输入框，可直接跳页。

效果：这 N 笔立即入账，离开待确认，统计随之更新。

**注意**：

- 分组已按「商户 × 平台 × 收支方向」自动分开，表格有「方向」列；确认前核对该组方向与所选类型一致，不要整组乱选。
- 系统不再根据批量确认自动创建规则；规则只由你操作 AI 显式写入（见第 5 节）。
- 历史批量确认已做规则清扫：命中内置交通规则的 14 条保留，其余 683 条已踢回待确认；你重新总结规则并让 AI 写入后，AI 会执行自动筛选。
- 做完分类区再去做退款：**退款只能关联"已经入账的消费"**，先确认消费，退款才有候选可关联。

### 第 2 步：高风险区 · 退款（64 条）

每条退款下方会列出候选原消费（退款日前 90 天内的已入账消费），显示日期、商户、金额、已退金额和匹配理由：

| 匹配理由 | 可信度 |
|---|---|
| 原交易订单号匹配 | 最高 |
| 商户单号匹配 | 高 |
| 同商户金额匹配 | 中 |
| 金额与时间窗口匹配 | 低（要自己核对） |

操作：选中正确的原消费 → 点「关联退款」。候选唯一时系统会自动冲销，不再需要你选。

效果：退款冲减那笔消费的实际成本（详情页能看到"实际成本"变小）；跨期退款会回写原消费所在月份。

**注意**：

- 如果显示"未找到候选原消费"，先回去把对应消费在分类区确认掉，再回来。
- 找不到候选、拿不准时**就放着**，退款绝不会被自动当成收入，不会污染统计。
- 一笔原消费可以分多次退；已退满的消费不会再出现在候选里。

### 第 3 步：高风险区 · 提现（5 条）

提现到银行卡时，平台不知道钱去哪了，必须你逐笔选「用途」：

| 用途 | 结果 |
|---|---|
| 未追踪账户调拨 | 记为调拨，不进消费/收入 |
| 投资 | 记为调拨（不计收支） |
| 现金消费 | **计入消费**，可填分类 |
| 其他 | 记为调拨 |

选好后点「确认用途」；"现金消费"可以顺手填个分类（如日常娱乐）。

### 第 4 步：高风险区 · 人际转账 / 其他中性资金流（137 + 66 条）

这些资金流方向不明（谁给谁、为什么），逐笔人工「定性为」：**消费 / 收入 / 调拨**，并填分类。例如：转给家人当饭钱 → 消费·日常三餐；朋友还钱 → 收入·其他收入；借出归还 → 调拨。

## 4. 概览（首页）

- 页面顶部可切换 **周 / 月 / 年**，并可点上一周期/下一周期，或用日期框跳到任意日期所在的周/月/年。
- 「关键指标」：总收入、总消费（退款后净额）、副业收入、副业成本、旅游消费、待确认数量。
- 「日常消费环比」：**只算日常类**（三餐/交通/学习/娱乐/缴费/医疗健康），旅游、副业、收入不混入。
- 「消费分类排行」：按净额排行。
- 兼容旧链接：`http://127.0.0.1:8000/?ym=2026-07` 仍打开 2026-07 月视图。
- 账单只覆盖到 2026-07-31，所以打开 2026-08 月视图显示全 0 是正常的；切到 7 月即可看到已确认数据。

## 5. 规则（让系统慢慢替你干活）

规则页可以：新建规则、查看列表、看命中历史、提升/停用/启用。

规则生命周期：

1. **观察期**（新建即观察期，批量确认 ≥2 项也会自动建）：命中时只**预填**分类、仍留在待确认，不自动入账。
2. 你连续验证几笔预填正确后，点「提升为自动入账」。
3. 之后新导入的账单命中该规则就**自动入账**，只有命不中的才进待确认。
4. 发现规则变错了：点「停用」（或重新启用）。

新建规则填：

- 匹配字段：「商户/交易对方」「商品/商品说明」或「原始交易分类」。
- 匹配内容：如 `美团外卖`、`闲鱼虚拟资料`。
- 平台条件：全部 / 支付宝 / 微信。
- 方向条件：全部 / 支出 / 收入 / 不计收支。
- 目标类型：消费 / 收入 / 调拨。
- 目标分类：如 日常三餐。

> 规则同时看匹配字段、平台和方向。**平台脱敏商户名（含 `*`，如 `****0`）不能作为规则条件**；批量确认这类组时会自动改用组内出现最多的商品说明建规则。
>
> **内置交通识别规则**：支出方向且商品说明含「地铁_ / 单车 / 骑行 / 公交 / 机票 / 火车票」，或商户名以「出行」结尾，会自动入账为「消费 · 出行交通」，不需要手工划分。
>
> **内置副业收入识别**：支付宝收入方向 + 交易对方被脱敏（含 `*`）+ 商品标题较长，或商户为「网易BUFF卖家」，自动归为副业收入。工资/报销不会命中。
>
> **闲鱼商品规则**：已总结的 22 个闲鱼商品名称分别写入 active 规则（详见 `docs/reports/37_*`）；再次卖出相同商品会自动归为副业收入。

## 6. 流水（查账、改错、补账）

「流水」页上半部是筛选：日期范围、关键词（商户/商品说明/单号/备注）、类型、分类、平台、来源状态、批次、"仅人工改动"。默认显示当前月。

表格每行有「详情」和「删」。

- **详情页**：显示账本记录、来源流水（哪个平台的哪笔单号）、退款关联明细、审计事件（这笔钱经过的每一步：批量确认/规则命中/人工修改/退款关联/高风险定性）。
- **人工编辑**：在详情页改类型/金额/分类/日期/备注并保存。改动会打上"人工"标记并写审计事件。
- **删除**：删掉一条账本记录（来源流水仍在库里）。**已关联退款的记录会被拒绝删除**（页面提示"删除失败"），退款关联只能保留，无法经删除解绑；普通记录删除前页面会要求确认。
- **误操作纠正**：详情页有「退回待确认」，把这笔删回待确认重新分类；如果整组批量确认错了，到「规则」页点该规则旁的「退回确认流水」一次退回整组。已人工编辑或已关联退款的记录会被系统保留并提示，不会静默删除。
- **简易补账**：账单里没有的钱（现金、银行卡、其他平台）手动补记：选类型、填金额（元，如 `12.34`）、分类、日期、备注 → 点「补记」。补记的记录无来源批次，撤销批次时不受影响。

## 7. 批次与撤销（导入历史 + 反悔机制）

### 导入

「导入」页选平台 + 选文件 → 点「导入并处理」。支持支付宝 CSV 和微信 XLSX，可一次一个文件。结果会显示：

| 字段 | 含义 |
|---|---|
| 总行数 | 文件里的交易行数 |
| 新增来源流水 | 真正入库的新交易 |
| 重复跳过 | 同平台来源单号已存在（重复上传不会产生重复流水） |
| 关闭/失败跳过 | 平台状态为关闭/失败/已撤销等的行，直接不导入 |
| 无效行 | 缺少交易单号的行 |
| 退款识别 | 识别为退款的行数（进入退款待办） |
| 自动入账 / 进入待确认 | 处理后分别去了哪里 |

**每周导新账单时，把支付宝和微信各导一次即可；老文件重复上传是安全的（全部被"重复跳过"）。**

### 撤销批次

「批次」页每行有「撤销」按钮。撤销会**删除该批次产生的账本记录和待办**，但有两条保护：

- 已被你人工编辑过的记录 → 阻塞，明确列出，不删。
- 已参与退款关联的记录 → 阻塞，明确列出，不删。

撤销适合"这份文件导错了/导重了"的场景。已撤销批次会保留一条记录（状态=已撤销）供追溯。

## 8. 数据安全与备份

- 数据库：`.data/ledger.sqlite`（单文件）。**建议每周导入新账单前手动备份**：复制该文件并加日期后缀，例如 `.data/ledger.sqlite-20260821.bak`。
- 备份文件也放在 `.data/` 下，不会进 git。
- 账单原始文件（含敏感信息）只放在项目外的 `D:\Mr.Q\掌控经济\消费记录`，**不要**复制进仓库或 docs。
- 撤销批次和删除流水都会真实改数据，操作前先想清楚；拿不准就先备份再操作。

## 9. 常见问题

| 现象 | 原因与处理 |
|---|---|
| 首页全是 0 | 当前月没有流水。用 `?ym=2026-07` 看有数据的月份，或导入新账单 |
| 退款显示"未找到候选原消费" | 原消费还没入账。先在分类区把该消费确认掉，再回来关联 |
| 退款没有合适的候选 | 候选只在退款日前 90 天内、且是已入账消费；候选**不限平台**（跨平台同商户也可能出现），注意核对商户与平台。拿不准就留着不处理 |
| 批量确认选错了分类 | 去「流水」找到那笔（按日期/商户筛选），详情页人工编辑改正 |
| 导入整个文件都错了 | 只要没编辑过、没关联过退款，直接到「批次」页撤销该批次 |
| 同一文件重复导入会怎样 | 全部计"重复跳过"，不产生新流水，可以放心重传 |
| 规则怎么不自动入账 | 观察期规则只预填、不自动入账；验证后到「规则」页点"提升为自动入账" |
| 提现为什么停在待确认 | 平台无法确定用途，必须逐笔选"未追踪账户调拨/投资/现金消费/其他" |
| 分类框没有下拉选项 | 待确认/流水/规则页已内置第 2.2 节正式分类；如仍需要自由输入，直接键入准确分类名即可 |
| 待确认里选错分类了 | 单笔去「流水」按关键词找到该笔 → 详情页「退回待确认」；整组选错去「规则」页点「退回确认流水」，然后回待确认重新选 |
| 流水怎么查找某笔交易 | 「流水」页用日期 + 关键词（商户/商品说明/单号/备注）搜索，再点「详情」 |
| 为什么不能建 `****0` 规则 | 那是支付宝脱敏后的商户名，没有业务意义；请改用商品说明，并指定平台/方向条件 |
| 商户名为什么有很多 `*` | `****0`、`x***2` 等来自支付宝账单导出时对交易对方的隐私脱敏，本应用原样保存、不会额外打码；请用商品说明与展开明细辨认 |
| 拼多多看不到商品信息 | 支付宝导出的账单对拼多多只给“拼多多平台商户 + 商户单号XP…”，没有商品名称；请回拼多多 App 按金额/时间查找，或留在待确认 |

## 10. 每周例行流程（建议）

1. 备份 `.data/ledger.sqlite`（复制加日期）。
