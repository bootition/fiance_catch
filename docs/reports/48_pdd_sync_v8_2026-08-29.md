# 48 拼多多订单同步与回填 v8 上线验收

**日期**：2026-08-29
**触发**：用户批准 `docs/decisions/04` 规格，要求将拼多多订单抓取/回填/退款订单链接建成长期功能，并处理退款误操作。

## 交付内容

### 功能
- schema v8：`pdd_sync_runs`、`pdd_orders`、`pdd_order_enrichments`、`pdd_order_enrichment_items`、`pdd_refund_order_links`；审计事件类型扩展 `refund_unlinked`、`pdd_enrich_applied`、`pdd_enrich_revoked`。
- `app/pdd/`：采集数据导入、标准化（含 goods_id/sku_id）、支出匹配、退款订单匹配、仓储与同步服务。
- `/pdd` 页面：同步状态、JSONL 导入并匹配、用已有订单重跑匹配。
- Inbox/分类区/流水/搜索/详情/退款匹配读取富化表，原始 `source_transactions.item_desc` 已恢复为账单原值。
- 退款匹配新增“拼多多订单号匹配”证据，得分 100 优先于商户单号匹配。

### 数据结果
- 导入订单快照：350 笔（2025-02-12 ~ 2026-08-25）。
- 支出富化：217 笔待确认支出中 high 211、manual_review 1、none 5。
- 退款订单链接：26 笔退款流水中 25 笔唯一候选 high，1 笔无候选。
- 误操作回滚：删除并重开错误退款链接 refund_source 1363/503（原误链到沙县小吃/京东同金额流水）。
- 全额退款冲抵：5 组微信“原支出已全额退款 + 退款收入”完成冲抵，净额 0；原消费账本分类留空待用户后续修改，note 标注 `[PDD退款冲抵]`。
- 原始数据恢复：此前 211 笔一次性写入 `item_desc` 的商品信息已迁入富化表，`source_transactions.item_desc`/`note` 恢复原值；另 5 笔冲抵来源同样恢复原 item_desc。

### 安全与回滚
- 迁移/写入前自动备份：`.data/ledger.sqlite-20260829-*.bak`（含 v8 迁移与退款修正两个独立备份）。
- 退款修正审计：`.planning/2026-08-28-pdd-long-term/pdd_refund_fix_audit.json`（不入 git）。
- 订单快照与网络日志位于 `.data/pdd/` 与 `.planning/`，均不入 git；cookie 值不落盘。
- 所有新增表写入均单事务；重新匹配采用 upsert，不删除历史订单。

- 守恒：流水全库 2322 行；拼多多 source 243 笔 ¥8,383.04；导入/退款修正后 ledger_entries 新增 5 笔（全部净额 0 的冲抵占位）。
