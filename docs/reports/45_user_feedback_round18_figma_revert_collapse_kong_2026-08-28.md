# 45 用户反馈第十八轮修复

**日期**：2026-08-28
**触发**：用户要求——Figma 金额不同回退；退款候选默认折叠并排除低分；孔夫子退款未处理原因说明。

## 1. Figma 退款已回退
- 已删除 Figma 的自动退款关联，并把退款待办重新打开。
- 匹配规则调整：退款金额 > 原消费金额时直接排除，不再生成候选。

## 2. 退款候选折叠与低分排除
- 候选列表默认折叠为「展开候选（N 条）」，不再默认铺开。
- 自动排除：
  - 金额不同且退款大于原消费 → 排除
  - 平台不同 → 排除
- 允许的只剩：
  - 同平台 + 同金额
  - 同平台 + 部分退款（退款 < 原消费，同商户/时间相近）

## 3. 孔夫子退款说明
原因找到了：
- 微信账单里“已退款(¥23.00)”且方向为支出的行，其实是**部分退款后的原消费**，不是退款本身。
- 之前解析器把这一行误判成退款待办，所以你在消费待办里看不到它。
- 已修复解析器，并回迁该笔：原消费 239.96 元已按「孔夫子旧书网 → 书籍学习」规则自动入账。
- 对应的 23 元退款现在有 6 个候选，其中：
  - `账本 #2615`，2025-10-18，孔夫子旧书网，239.96 元 —— 就是对应原消费
  - 其余是同日同商户的其它订单
- 系统不自动猜；展开候选后选择 **#2615** 即可。
