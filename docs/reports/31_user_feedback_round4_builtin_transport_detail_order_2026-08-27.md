# 31 用户反馈第四轮修复

**日期**：2026-08-27
**触发**：用户反馈——① 明细应放在栏目上方；② 美团里餐饮和交通混在一起，地铁/单车等明显交通特征应直接改规则区分，减少手工分类。
**范围**：`/inbox` 明细布局、内置高置信交通识别规则、既有 unmatched 队列一次性应用。

## 1. 明细位置

分类区每个分组现在先渲染「查看 N 笔明细」展开区，再渲染商户/平台/方向/金额等栏目行。用户展开后先看明细，再决定是否整组确认。

## 2. 内置交通识别规则

内置规则（硬编码，产品级默认值，不占用用户可停用规则表）：

| 条件 | 结果 |
|---|---|
| 支出方向 + 商品说明含 `地铁_` | 消费 · 出行交通 |
| 支出方向 + 商品说明含 `单车` | 消费 · 出行交通 |
| 支出方向 + 商品说明含 `骑行` | 消费 · 出行交通 |
| 支出方向 + 商品说明含 `公交` | 消费 · 出行交通 |

说明：
- 用 `地铁_` 而不是 `地铁`，避免把“蜜雪冰城（沙河地铁站松兰路店）”误判为交通。
- 新导入账单命中即自动入账；规则页有内置规则说明卡。
- 不匹配收入/退款/不计收支方向。
