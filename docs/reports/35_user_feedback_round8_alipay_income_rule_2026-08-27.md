# 35 用户反馈第八轮修复

**日期**：2026-08-27
**触发**：用户反馈——大量收入未归类；支付宝账单上的闲鱼收入应归为“副业收入”。
**根因**：这些收入行的商户名被支付宝脱敏（`****0` 等），商品说明是课程/资料标题，账单文本中并未出现“闲鱼”字样；此前只写了「商品说明含闲鱼」规则，因此没有命中。平台和原始交易分类其实是可用的：`platform=alipay`、`raw_type=收入`。

## 修复

1. schema v7：`classification_rules.match_field` 允许匹配 `raw_type`（原始交易分类）。
2. 新增并提升 active 规则：
   - 匹配字段：原始交易分类
   - 匹配内容：`收入`
   - 平台：支付宝
   - 方向：收入
   - 目标：收入 · 副业收入
3. 运行 `apply_all_rules_to_pending()`，把全部 155 条未匹配的支付宝收入入账为「副业收入」。

## 数据结果（正式库已执行）

- v6→v7 自动备份：`.data/ledger.sqlite-20260827-230030.bak`
- 本轮自动入账：**155 笔**
- 收入方向未匹配：155 → **0**
- 待确认：1386 → **1231**（unmatched 988 + 高风险 243）
- 账本：936 → **1091**
- 规则表：17 → **18 条 active**

## 说明

当前账单中支付宝 `raw_type=收入` 的交易均为闲鱼虚拟资料销售收入，因此按用户指引统一归为“副业收入”。如果未来支付宝出现工资/报销等其它收入，应再增加更具体的 raw_type/商户规则，而不是继续依赖这条宽规则。
