# 41 用户反馈第十四轮修复

**日期**：2026-08-28
**触发**：用户询问关联退款机制，要求只要退款与花费金额能冲抵、不造成虚假财产即可，并希望检测到后自动冲销。

## 1. 关联退款是什么

退款不是收入。系统会把退款与一笔原来的消费关联：

- 原消费 100 元，退款 100 元 → 该笔消费净额为 0。
- 原消费 100 元，退款 60 元 → 该笔消费净额为 40。
- 概览和分类排行都按冲抵后的净额统计。

这就是“冲销”，目的是避免把退款错记成收入，从而虚增财产。

## 2. 为什么之前没有自动冲销

此前系统只生成候选、由用户手工选择，主要担心金额相同的多笔消费难以区分。现在按用户口径改为：

**候选唯一时自动冲销；候选为 0 或多于 1 时保留人工处理。**

- 候选唯一：系统直接自动关联，不再询问。
- 候选多个：说明有多笔金额/商户相近的消费，系统不猜，仍显示 `账本 #ID + 日期 + 原交易单号` 让你选。
- 候选为 0：通常是原消费还在待确认未分类；分类完成后再次运行规则筛选，候选出现后会自动冲销。

- 多候选：金额/商户相近，保留人工选择以防冲错对象。

## 4. 后续机制

`apply_all_rules_to_pending()` 每次运行规则筛选后，会自动执行一次“唯一候选退款自动冲销”。因此你后续总结规则、让我写入并筛选时，可自动消化的退款会持续减少。
