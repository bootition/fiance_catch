## Finding

### P1：空交易时间行被静默丢弃且导入显示成功

**位置：** `app/importing/alipay.py:93-97`

支付宝解析器在处理表头后的每一行时执行：

```python
if not cells[COL_TIME]:
    continue
```

这发生在 `normalize_occurred_at()` 前。因此“列结构完整、交易状态成功、金额有效，但交易时间为空”的数据行不会抛 `ValueError`，而是被静默忽略。

红队复现：上传只含一条空交易时间成功交易的支付宝 CSV。结果为 HTTP 200、创建 1 个导入批次、来源流水为 0。用户看到的是成功导入零行，而非需要重新导出的异常账单提示。

金融账本不应静默丢弃有效格式的异常流水。空时间可能来自导出截断、文件损坏或字段错位；其正确处理应是整批失败，而不是跳过。

**修复要求：**

1. 只跳过真正完全空白的 CSV 行；对表头后的非空数据行，空交易时间必须调用 `normalize_occurred_at()` 并抛 `ValueError`。
2. 对微信同样区分完全空白行与缺失交易时间的数据行。
3. 添加支付宝/微信空交易时间 HTTP 端到端测试，断言错误页、0 批次、0 来源流水、临时文件已清理。
4. 重新运行完整测试与红队复审后再进入阶段七。

## 是否可进入阶段七
